# 전화 상담과 지자체·병원 대시보드 로컬 실행

이 프로젝트는 브라우저에서 전화 상담 흐름을 확인하는 개발 환경입니다. 실제 전화망이나 병원 EMR은 연결되어 있지 않으며, `070-1122-3344`의 착신 가능 여부도 확인되지 않았습니다. 실제 환자의 개인정보와 의료정보를 입력하지 마세요. 사용자 제공 의료 JSON은 의료진 검증 전 개발용 참고자료입니다.

## 준비

Windows PowerShell, `uv`, Python 3.11과 3.14가 필요합니다. `backend/.env`에서 Gemini 및 ElevenLabs, 병원 대시보드와 공공데이터포털 인증 정보를 설정합니다. 음성 인식에는 Azure Speech 리소스의 키와 지역이 필요합니다.

```dotenv
AZURE_SPEECH_KEY=<Azure Speech 리소스 키>
AZURE_SPEECH_REGION=<Azure Speech 리소스 지역>
HOSPITAL_DASHBOARD_URL=http://127.0.0.1:8767
HOSPITAL_DASHBOARD_TOKEN=<로컬 병원 대시보드 공유 토큰>
MUNICIPAL_INTAKE_URL=http://127.0.0.1:8767
MUNICIPAL_INTAKE_TOKEN=<전화 서버와 지자체 수신 서버의 독립 인증값>
MUNICIPAL_STAFF_TOKEN=<지자체 직원 화면 인증값>
```

`.env`는 비밀 파일입니다. 실제 키를 채팅이나 저장소에 올리지 마세요. 같은 이름의 프로세스 환경변수가 있으면 `.env` 값보다 우선합니다. 설정을 변경했다면 서버를 다시 시작하세요. 병원 검색에는 공공데이터포털에서 승인된 심평원 인증키 `DATA_GO_KR_SERVICE_KEY`도 필요합니다.

환자는 내부 서비스 토큰을 입력하지 않습니다. 로컬 전화 화면은 통화별 접근값을 사용합니다. 지자체 직원은 `MUNICIPAL_STAFF_TOKEN`, 병원 담당자는 `HOSPITAL_DASHBOARD_TOKEN`을 사용하며, 전화 AI의 지자체 서버 전송에는 별도의 `MUNICIPAL_INTAKE_TOKEN`을 사용합니다. 세 값은 각각 달라야 합니다. 내부망만으로 사용자의 신원과 접근 권한이 확인되는 것은 아니므로 실제 운영 시에는 병원·지자체 직원별 인증과 권한 관리가 추가로 필요합니다.

## 시작과 종료

프로젝트 루트에서 다음을 실행합니다.

```powershell
.\start-local.ps1
```

필요한 패키지를 준비하고 전화 AI와 대시보드를 별도 프로세스로 실행합니다. 8000 또는 8767 포트가 이미 사용 중이면 기존 서버를 건드리지 않고 중단합니다. 실행에 성공하면 주소와 프로세스 ID가 출력됩니다.

- 전화 화면: http://127.0.0.1:8000/ui/
- 지자체 대시보드: http://127.0.0.1:8767/municipality
- 병원 대시보드: http://127.0.0.1:8767/

종료할 때는 시작 명령이 출력한 실제 프로세스 ID를 사용하세요. 아래 숫자는 예시입니다.

```powershell
.\stop-local.ps1 -PhonePid 1234 -DashboardPid 5678
```

별도의 발신 준비 화면에서 발신번호를 입력하고 첫 음성의 Azure 처리 안내를 확인한 후 다이얼 화면에서 전화를 겁니다. 브라우저의 마이크·기기 위치 권한은 발신 전에 요청합니다. 이 과정에서 얻은 기기 위치는 브라우저 메모리에 임시 보관하며, 통화 중 동의 전에는 병원 검색이나 서버 전송에 사용하지 않습니다. 거절하거나 통화를 마치면 임시 위치를 폐기합니다.

통화가 시작되면 전화번호·건강 상담 내용·위치 사용, 지자체 보관과 직원 확인 후 병원 인계, 외부 음성·AI 서비스 처리 범위를 한 번 안내하고 음성 동의를 받습니다. 안내가 끝난 뒤 “동의합니다”, “어, 동의했어”처럼 명확히 동의하면 위치를 다시 묻지 않고 상담을 시작합니다. 동의가 모호하거나 일부 범위에 대한 거절이 섞이면 임의로 전체를 수락하지 않고 다시 확인합니다. 통화 중 별도의 조작 버튼 없이 문의와 종료를 말로 진행합니다. 동의 답변 자체는 Azure Speech에 전송해 인식하므로 실제 운영 전 고지·동의 방식 검토가 필요합니다.

동의 판정은 동의 전 발화가 Google에 추가 전송되지 않도록 로컬에서 보수적으로 처리합니다. 동의 이후에는 저지연 Gemini가 현재 발화와 같은 통화의 최근 문맥을 받아 종료·병원 요청·상담·동의 철회 등의 의도를 분류합니다. 분류가 불확실하거나 실패하면 짧게 다시 묻고 임의로 진행하지 않습니다. 응급 표현은 모델 결과를 기다리지 않고 기존 긴급 경로를 우선합니다. 최종 상담에는 별도로 설정된 고추론 모델과 ElevenLabs 음성을 사용합니다.

답변이나 병원 안내를 마친 뒤에도 통화를 유지합니다. “고마워요”, “잘 모르겠어요”, “병원에 가볼게요”만으로 종료하지 않습니다. 이미 답한 내용은 같은 통화의 문맥으로 활용하고, 현재 질문을 우선해 한두 문장과 필요한 질문 하나로 안내합니다. 명확히 끊겠다는 요청에는 종료 안내 음성 생성을 기다리지 않고 `/calls/{call_id}/end`로 종료를 기록합니다. 통화 종료는 동의 철회와 별개이며 이미 동의하고 완료한 상담 기록을 삭제하지 않습니다. 진행 중인 응답은 취소하고 뒤늦게 도착한 답변·음성을 사용하지 않습니다. 브라우저 화면을 닫는 경우에도 종료를 요청하지만 네트워크 단절이나 브라우저 강제 종료 시 전달은 보장하지 않습니다.

일시적인 응답·음성 합성 오류나 재생 기록 전송 실패가 곧 통화 종료를 뜻하지는 않습니다. 가능한 경우 짧게 재안내하고 다시 말할 수 있게 합니다. HTTP 요청은 응답 본문 수신까지 제한 시간을 적용합니다(일반 요청 15초, 음성 45초, 병원 조회 60초). 이 시간은 실제 응답 속도 보장이 아닙니다. 마이크 해제, 권한·인증 만료, 동의 거절·철회 등 상담을 계속할 수 없는 조건에서는 중단 사유를 표시합니다. 음성 인식 세션과 접근값 자체의 수명 제한도 남아 있습니다.

지자체 화면에서 `MUNICIPAL_STAFF_TOKEN`으로 접속하면 미확인 접수와 긴급 건을 볼 수 있습니다. 상담을 열어 **상담 내용 확인**을 기록한 뒤 **병원 대시보드에 인계**를 선택합니다. 직원 인증값은 화면 메모리에서만 사용하며 화면을 잠그면 지워집니다. 화면이 열린 동안 약 8초마다 새 내용을 확인하고, 브라우저 권한이 허용된 백그라운드 페이지에는 시스템 알림을 표시할 수 있습니다. 화면을 닫았거나 연결이 끊긴 동안의 알림은 보장하지 않습니다.

일반 음성 안내가 재생되는 동안에도 Azure Speech의 중간 인식으로 사용자 발화가 감지되면 재생을 중단하고, 확정 인식 결과를 상담에 사용합니다. 마이크는 우선 브라우저에 시스템 출력 전체의 에코 제거(`echoCancellation: "all"`)를 요청합니다. 지원하지 않으면 일반 에코 제거(`true`)로 전환합니다. 권한 거부는 다시 요청하지 않습니다. 마이크의 에코 제거 설정이 활성화되지 않았거나 해당 음성의 실제 발화 문구를 확인할 수 없으면, 자기 음성을 사용자 발화로 오인하지 않도록 일반 끼어들기를 제한합니다. 긴급 징후는 중단 처리보다 우선합니다. 개인정보 안내가 끝나기 전에 말한 동의는 승인하지 않고 안내 후 다시 확인합니다.

에코 제거 설정은 스피커 음성과 사용자 음성을 완전히 분리한다는 보장이 아닙니다. 테스트 기기에서 `"all"` 설정은 적용됐지만 스피커 신호가 마이크에 도달하는 경로를 확인하지 못해 에코 감소나 동시 발화 인식 개선은 측정하지 못했습니다. 스피커 소리와 사람이 동시에 말하면 사용자 발화가 누락되거나, 안내 음성을 긴급 발화로 잘못 판단할 수 있습니다. 짧은 답변은 재질문될 수 있습니다. 합성 음성과 가상 마이크로 실제 Azure 연결을 시험했지만, 물리 스피커·마이크 조합과 실제 전화 회선에서의 안정성은 검증되지 않았습니다. 세션 시간 초과와 늦게 도착하는 인식 결과의 손실 가능성도 남아 있어 실제 응급 상담에 사용해서는 안 됩니다.

## 위치와 병원 추천

새 통화의 통합 동의는 위치 사용을 포함합니다. 과거 별도 위치 동의를 받도록 만든 통화에는 이 범위를 소급 적용하지 않습니다. 기기 위치를 사용하면 **해당 브라우저가 설치된 기기의 위치**이며 전화 발신자의 위치와 다를 수 있습니다. 일반 전화의 발신번호만으로 GPS 위치를 알 수 없습니다. 음성으로 말한 주소를 좌표로 바꾸는 기능은 아직 연동되어 있지 않습니다. 위치 권한이 거절되거나 위치를 구할 수 없으면 위치 기반 추천을 제공할 수 없습니다.

추천은 관련 진료과가 확인된 병원을 먼저 고르고, 각 그룹 안에서 반올림 전의 직선거리가 짧은 순으로 정렬합니다. 진료과가 확인되지 않은 병원과 등록 목록에 없는 병원은 별도로 구분하며, 정확히 같은 거리일 때 등록 전문의와 요일별 진료시간을 보조 기준으로 사용합니다. 가능한 진료과는 심평원 조회에 해당 과목 코드를 넣어 반경 2·5·10·20·30km를 차례로 확인합니다. 해당 범위에서 일치 후보가 없으면 주변 의료기관을 다시 조회하고 그 사실을 알립니다. 좌표가 확인된 후보 중 가까운 최대 30곳만 상세 평가하므로 반경 밖 또는 평가 대상 밖의 더 적합한 병원이 없다는 뜻은 아닙니다. 진료과 정보가 불명확하거나 해당 과 코드를 제공하지 않으면 일반 주변 목록을 검색합니다.

API의 `score`는 호환용 정렬 참고값이며 의료의 질이나 실제 진료 가능성의 확률이 아닙니다. 화면에서는 점수를 보여주지 않습니다. 등록 진료시간은 임시휴진과 공휴일 등을 반영하지 않을 수 있고 전문의 등록도 현재 근무를 의미하지 않습니다. 방문하기 전에 의료기관에 진료 여부를 확인해야 합니다. 응급 가능성이 감지되면 일반 추천보다 긴급 안내가 우선됩니다.

상담은 병원 방문을 준비하는 데 필요한 안내를 중심으로 진행합니다. 예를 들어 자료나 모델 응답을 확인하지 못할 때는 진단을 추측하지 않고 신분증과 복용 중인 약 또는 약봉투를 준비하라고 알린 뒤 병원 찾기를 제안합니다. 이 경우도 처리 상태와 오류 원인은 별도로 기록합니다. 사용자가 동의하면 같은 통화의 문맥을 바탕으로 병원 검색을 진행하며, 필요한 진료과가 불명확하면 확인합니다.

병원을 안내한 뒤에는 같은 통화에서 조회한 공개 병원 정보로 전화번호·주소·진료시간 등의 후속 질문에 답할 수 있습니다. 주소는 조회된 병원 자체의 공개 주소이며 발신자의 주소나 좌표가 아닙니다. 길 안내·이동 경로 계산과 말로 받은 주소 검색은 지원하지 않습니다. 확인되지 않은 시간, 전문의 근무 여부, 예약·접수 완료를 만들어 말하지 않습니다. 위치 사용을 철회하면 이전 위치로 조회한 병원 문맥과 그 정보에서 파생된 과거 답변을 새 모델 입력에 사용하지 않습니다. 방문 준비와 다른 질문은 가능한 범위에서 이어가며 같은 준비물 안내를 매번 반복하지 않습니다.

응급 감지는 일부 발화 패턴에 대한 개발용 규칙이며 임상 선별 시스템이 아닙니다. 명확한 부정이나 오래전 사건을 현재 증상으로 오인하는 경우를 줄였지만 STT 오류, 문맥과 표현 차이로 긴급 상황을 놓치거나 오탐할 수 있습니다. 현재 진행 중인 위험 신호는 일반 병원 추천보다 긴급 안내가 우선됩니다.

동의 후 긴급 경로로 전환되어도 즉시 자동 종료하지 않습니다. 저지연 모델은 연락 가능 여부와 주변 도움, 명확한 종료·동의 철회만 해석하며 응급 상태를 해제하거나 일반 병원 추천으로 돌아가지 않습니다. 안내 중에도 분리해 인식된 종료·철회 발화는 처리합니다. 실제 신고·출동·전화 연결을 수행한 것처럼 말하지 않습니다. 동의 전 긴급 발화는 고정 안내 후 음성 처리를 중단하고, 후속 상담이나 지자체 전송으로 진행하지 않습니다.

정확한 GPS 좌표 자체는 SQLite에 저장하지 않습니다. 동의 후 추천 정보의 병원명과 거리 등으로 대략적인 위치가 추정될 수 있습니다. 위치나 상담 정보 처리 동의를 철회하면 이후 처리를 중단하고 해당 대기 추천을 취소합니다. 이미 지자체·병원에 전달됐거나 철회와 동시에 전송 중인 정보는 자동으로 회수되지 않습니다. 자료는 [심평원 병원정보서비스](https://www.data.go.kr/data/15001698/openapi.do)와 [의료기관별상세정보서비스](https://www.data.go.kr/data/15001699/openapi.do)를 사용합니다.

## 저장과 대시보드 전달

전화 AI와 지자체·병원 대시보드는 서로 다른 SQLite 파일을 사용합니다. 전화 AI는 `HOSPITAL_DB_PATH`를, 대시보드는 `external/KimJangCheol/backend/.local-data/hospital.sqlite3`을 사용합니다. 시작 스크립트는 두 경로가 같으면 실행하지 않습니다. 상담 동의를 받은 전화는 먼저 지자체의 보호된 접수함으로 전달합니다. 지자체 직원이 확인하고 병원 인계를 선택하기 전에는 병원 상담함에 자동으로 전달하지 않습니다. 긴급 표시도 지자체 접수함에서 확인하지만, 이를 119 신고나 출동으로 오해해서는 안 됩니다.

사용자가 응답을 끊으면 기존 질문은 남기고 답변은 중단 상태로 기록합니다. 지자체에는 중단 사실이 전달되며, 이미 보낸 답변이나 전송 중인 정보는 자동으로 회수되지 않습니다. 최종 음성이 브라우저에서 끝까지 재생된 경우에만 재생 완료를 기록하며, 이는 사용자가 실제로 듣거나 이해했다는 증거는 아닙니다. 지자체에 새 상태가 도착한 뒤 직원이 확인하고 다시 인계해야 병원 화면에도 반영됩니다.

지자체 제공 안내에 동의한 통화만 전달 대상입니다. `municipality-v3` 통화는 새 통합 안내에 대한 동의와 위치 이용 동의를 함께 기록합니다. 이전 `municipality-v2` 통화의 위치 이용은 기존 별도 동의 기록을 따르며, 이전 동의를 새 통합 동의로 바꾸지 않습니다. 지자체 제공에 동의하지 않은 더 오래된 통화는 자동으로 이관하지 않습니다. 전송 대기열은 서버가 실행 중일 때 약 5초마다 복구와 재시도를 수행하며 이벤트 ID로 중복 접수를 방지합니다.

동의 이전에 긴급 발화가 감지되더라도 음성 안내는 우선하지만, 전화번호나 발화 등 개인정보는 지자체로 전송하지 않습니다. 따라서 동의 전 긴급 상황은 지자체 자동 알림으로 전달되지 않습니다.

병원 인계는 이 로컬 대시보드 DB의 병원 수신 기록에 저장하는 것입니다. 외부 병원 서버에 실제 전송하거나 병원 접수·예약을 확정하지 않습니다. 지자체 알림은 열린 대시보드에서 수신 상태를 확인하는 기능이며, 브라우저가 닫힌 상태의 푸시는 보장하지 않습니다. 시스템 연결이 실패한 건의 전송 상태를 확인해야 합니다.

현재 병원 추천 결과는 위치 동의 철회와 인계가 동시에 일어나는 경우를 검증 중이므로 지자체·병원으로 자동 전달하지 않습니다. 전화 화면에서 안내된 추천과 지자체 직원이 인계한 상담 내용은 구분해야 합니다.

추천 결과 API에는 공개 병원 주소가 선택 필드로 추가됐습니다. 이전 자료에 주소가 없어도 읽을 수 있습니다. 다른 서버에 이 계약을 적용할 때는 수신 서버를 먼저 갱신해야 하며, 이 로컬 코드 수정이 공개 배포 서버를 자동으로 변경하지 않습니다.

모델 응답이 JSON 형태여도 화면과 병원 대시보드에는 표시용 문장을, TTS에는 음성용 문장을 사용합니다. 이전에 JSON 전체로 합성된 음성은 재생하지 않습니다.

## 남은 연동과 검증

- Azure Speech 키와 지역이 준비되어야 실제 음성 인식을 시험할 수 있습니다. 설정만으로 실사용 품질이 보장되지는 않습니다.
- Azure Speech SDK의 인식 시작·중지 네이티브 호출이 멈추면 정리 완료 시간이 보장되지 않습니다. 실제 운영 전 별도 프로세스 격리와 장애 복구 방식을 검토해야 합니다.
- 전화번호의 실제 착신, 통신사 연동과 통화 음성 전송은 구현되지 않았습니다. 일반 전화의 위치 취득과 주소 확인 방식도 별도로 연동해야 합니다.
- 전화 다이얼과 통화 화면에는 제공받은 Figma Make ZIP의 디자인을 반영했습니다. 원본 다이얼과 비교했고, 발신 준비 화면과 대화 표시를 추가했으며 음성 전용 요구에 따라 통화 중 조작 버튼을 제거했습니다. ZIP에는 병원 대시보드 원본 디자인이 없습니다.
- 현재는 개발 환경입니다. 평문 SQLite, 자료 보존·삭제, 의료진별 접근 제어, 의료 내용 검증, 응급 처리, 개인정보·위치정보와 외부 서비스 제공 고지 등 실제 운영 조건을 검토하고 개선해야 합니다.

오류 로그는 시작 스크립트가 출력한 임시 폴더에 저장됩니다.
